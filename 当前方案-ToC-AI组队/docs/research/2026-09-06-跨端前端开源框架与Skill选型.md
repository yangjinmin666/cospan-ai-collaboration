# 跨端前端开源框架与 Skill 初步选型

核验日期：2026-09-06。用途：为 COSPAN 的「微信小程序 + 移动 H5 + 可安装 App」提供初选清单；本记录不是迁移决策，也未执行安装、代码改动、提交或构建验证。

## 当前背景与结论

按本轮项目上下文，COSPAN 目前是普通移动 Web、承载 Web 的 Android WebView 壳，以及另行维护的微信原生小程序。若目标是从一套前端源码维护三个端，可以先评估 uni-app；若愿意采用 React 并承担 React Native 工具链，则评估 Taro；Mpx 是更贴近微信小程序语法、也支持 React Native 的备选。这是基于技术路径的判断，尚无本项目迁移成本与真机体验的实测。

框架承担编译、组件与运行时适配；Agent Skill 提供开发指导，两者不能互相替代。现有普通 HTML/DOM 页面也不能通过安装 Skill 自动变成三端通用源码。

## 官方资料核验

| 候选 | 微信小程序与 H5 | 可安装 App 的实际路径 | 本项目初步适用判断 |
| --- | --- | --- | --- |
| [uni-app](https://github.com/dcloudio/uni-app) | 官方 README 列出微信等小程序与 Web；基于 Vue 生态 | 当前 README 区分传统 uni-app（JS 逻辑层，WebView 渲染）与 uni-app x（App 原生渲染）；评估时必须明确产品分支与版本 | 三端目标直接契合，建议列为首个验证候选；不能将传统版本与 x 的能力、约束混用 |
| [Taro](https://github.com/NervJS/taro) | README 列出 React/Vue 等框架及微信小程序/H5 | 官方 RN 开发文档限定为选择 React 的 Taro 项目，适配后输出 RN bundle，再通过 Android/iOS 原生工具打包 | React 路线候选；不能把“支持 Vue”推导为 Vue 项目也可直接走同一 RN 路线 |
| [Mpx](https://github.com/didi/mpx) | README 列出小程序及 Web 输出，以类 Vue / 微信增强语法开发 | 当前 README 明确支持 RN iOS/Android/Harmony；输出 JS bundle 和资源，原生容器、签名、打包、发布仍由对应工具链完成 | 小程序优先或需要保留微信语法习惯时值得验证；“Mpx 不支持 App”已不符合当前官方资料 |

### 为什么不能承诺 100% 复用

uni-app 官方[条件编译文档](https://uniapp.dcloud.net.cn/tutorial/platform.html)明确指出每个平台有自身特性，存在无法跨平台的情况，并提供 API、组件、样式、页面配置及资源的条件编译。Taro 的[RN 开发注意事项](https://docs.taro.zone/docs/react-native-remind)说明 RN 样式与 Web CSS 有差异，需要按各端约束组织布局与条件样式。Mpx README 也介绍 `.ios.mpx`、`.android.mpx`、`.harmony.mpx` 等平台差异文件。

因此应把共享业务状态、接口调用、主要页面与组件作为目标，同时预留登录授权、分享、文件上传、通知、键盘、安全区及系统返回等平台适配。具体共享比例必须在 COSPAN 的真实页面和核心流程上验证，不能从框架宣传推算。

## 可搭配的社区 Skill

[uni-helper/skills](https://github.com/uni-helper/skills) 的 README 包含由 uni-app 官方文档生成的技能，以及 Vue、Pinia、Vite 等相关技能。主任务已核验实际 uni-app 技能目录为 `skills/uniapp`；README 显示的 `skills/uni-app` 路径与实际目录存在差异，使用前应核对仓库。

其 README 明确写道：

> 这是一个概念验证项目，用于从源文档生成 agent 技能并保持同步。
> 我还没有充分测试这些技能在实际中的表现。

因此可列为 uni-app 开发的知识辅助候选，属于社区项目，不能称作 DCloud 官方认证 Skill。“来自官方文档”说明内容来源，不等于官方维护、效果保证或适用于所有 uni-app x 版本。此轮未安装或执行仓库中的脚本，也未实际测试技能表现。

## 进入迁移决策前的最小验证建议

选一个含列表、详情、表单和登录态的真实业务切片，验证微信开发者工具、手机浏览器与 Android 安装包三个目标的核心流程；记录共享文件、平台差异、构建步骤与视觉偏差。再基于结果决定是否替换当前 Web + Android 壳 + 独立小程序。iOS 若纳入发布范围，另行完成 iOS 真机与签名构建验证。

## 补充：传统 uni-app Vue3 的静态可行性评估

追加日期：2026-09-06。本节针对传统 uni-app Vue3，明确排除将 uni-app x、nvue 原生渲染能力直接套用到 App-vue。只读取官方资料，未搭建原型或修改产品、素材。

### 对当前合拍 / COSPAN 最小改动的路线

建议优先验证「uni-app Vue3 编译 H5 与 mp-weixin，H5 继续由现有 Android WebView 壳承载」。这复用现有 App 容器，首轮不必引入 App-plus 或 React Native。此判断是工程复杂度的静态判断，不代表已经验证 H5 产物在现有壳中可无改动运行：路由、系统返回、定位、认证回跳、App Link / 深链及 WebView 桥接仍需测试。

Taro 也可以只输出 H5 与小程序并保留原壳；若选择 Taro RN，则额外增加 React Native 依赖、原生工程与组件样式约束。当前已有可安装的 WebView Android App，因此“获得可安装 App”本身不足以成为立即切换 RN 的理由。需要原生交互或性能且验证现有壳不能满足时，再评估这一条路线。

### 官方约束与项目影响

| 项目 | 已核验的官方证据 | 对迁移的含义 |
| --- | --- | --- |
| DOM / 浏览器对象 | [JS 语法文档](https://uniapp.dcloud.net.cn/tutorial/syntax-js.html)：H5 运行于浏览器；非 H5 的业务 JS 不支持 `window`、`document`、`navigator`；App-vue 的渲染在 WebView，业务 JS 在独立引擎 | 现有普通 Web 的 DOM 操作不能直接变成共享业务代码。即便 App-vue 使用 WebView，也不等于现有完整网页脚本可以原样放进 App-vue |
| renderjs 特例 | [renderjs](https://uniapp.dcloud.net.cn/tutorial/renderjs.html) 只支持 App-vue 与 Web，可在视图层操作 DOM，明确不支持微信小程序 | 只能作为特定端适配方式，不能解决三端通用 DOM 库问题；共享界面优先使用响应式数据与框架组件 |
| 条件编译 | [平台差异文档](https://uniapp.dcloud.net.cn/tutorial/platform.html) 支持 H5 / MP-WEIXIN / APP-PLUS 等，覆盖 API、组件、样式和资源 | 可保留登录、分享、权限等平台适配；不能把“使用条件编译”当作无需测试平台差异 |
| WebView 与原生 | [JS 语法文档](https://uniapp.dcloud.net.cn/tutorial/syntax-js.html) 区分 vue 页面使用系统 WebView，nvue 使用原生 View；CSS 兼容性受系统 WebView 影响 | 首轮维持 H5 + 现有壳最贴近现状。若未来选择 App-vue，要单独验证独立 JS 引擎与桥接；原生渲染属于另一评估范围 |
| SVG | [image 组件文档](https://uniapp.dcloud.net.cn/component/image.html) 写有“小程序上只支持网络地址的 svg 图”，同时列举不同渲染方式的格式差异 | 这是 uni-app 组件文档的兼容提示，不能推断所有微信原生小程序均不支持本地 SVG。主任务已确认现有原生 mini 的本地 SVG 路径与编译测试；后续只应测试框架 image 的实际产物，不据此批量改现有素材 |
| 动画 | [uni.createAnimation](https://uniapp.dcloud.net.cn/api/ui/animation.html) 列出 App、H5、微信支持，明确 nvue 暂不支持；[renderjs](https://uniapp.dcloud.net.cn/tutorial/renderjs.html) 无微信支持 | transform / opacity 等基础动画有共享实现候选。依赖 DOM 或浏览器 API 的动画库仍需适配；“官方 API 支持”不等于当前所有动画效果、流畅度一致 |
| 音频 | [音频上下文文档](https://uniapp.dcloud.net.cn/api/media/audio-context.html)：`autoplay` 在 H5 部分浏览器不支持；`src`、静音开关、倍速等列有平台差异 | 若现有流程涉及音频，应逐项验证用户触发播放、暂停、页面切换与后台状态、格式和错误恢复；不能假设 HTML Audio / Web Audio 代码原样覆盖三端 |

### 构建与费用边界

官方[CLI 快速开始](https://uniapp.dcloud.net.cn/quickstart-cli.html) 提供 Vue3/Vite JS 和 TS 模板，可使用 Node/npm 管理依赖，分别构建 H5 与微信小程序。文档列出的 `app-plus` 构建产物是 App 打包资源，不是已签名 APK / IPA；实际脚本名以选定模板为准。该文档同时说明 App 运行调试和发布涉及 HBuilderX。若首轮仅构建 H5 并使用现有 Android 壳，就沿用现有壳的原生打包流程，不把 App-plus 工具链引入首轮。

如果未来改用 uni-app App 打包，至少需要区分：

- 云端打包：[官方云端环境](https://uniapp.dcloud.net.cn/tutorial/app-env.html) 列出随 HBuilderX 版本变化的 Android SDK、Gradle、JDK、Xcode 与 iOS SDK，说明云端承担了原生编译环境，不能理解为“没有原生构建依赖”。
- 本地离线打包：[Android 离线 SDK 集成](https://nativesupport.dcloud.net.cn/AppDocs/usesdk/android.html) 需要 Android Studio / 原生工程与 DCloud SDK，并要求 SDK、aar/jar、构建配置配套更新；[App 基础配置](https://uniapp.dcloud.net.cn/tutorial/app-base.html) 说明离线打包的原生工程需要设置 DCloud appid 等信息。
- 成本和许可：本轮没有完成 DCloud SDK、HBuilderX、云服务、插件及平台账号的逐项条款审计，因此不能把 GitHub 仓库开源推导成“整个工具链全 MIT”或“所有打包与发布服务永久免费”。精确费用与服务条款需在实际选定打包路线后按当时官方说明核验。

结论限于静态可行性：传统 uni-app Vue3 值得进入 H5 + 微信小程序的最小验证；现有 Android 壳可以作为拟保留的容器。是否正式迁移、是否采用 App-plus，以及视觉和业务代码能复用多少，仍由源码审查与三端实际验证决定。
