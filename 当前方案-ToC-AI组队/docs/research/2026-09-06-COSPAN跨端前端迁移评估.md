# COSPAN 跨端前端迁移评估

日期：2026-09-06。状态：静态代码与官方资料评估；未安装框架、未构建跨端原型、未测量迁移后性能。本报告不是迁移完成证明，也不授权替换现有生产/预览入口。

后续记录（2026-09-07）：用户批准后已实施隔离切片，交付与未完成验收见 [跨端验证 README](../../prototype/cross-platform-spike/README.md)。下文保留评估时点的判断，不代表已通过全部迁移门槛。

## 结论

建议进入 **传统 uni-app Vue 3 + TypeScript 的隔离验证**，不立即全量迁移。首轮目标为同一移动端源码输出 `mp-weixin` 与 H5；H5 构建产物尝试继续放入现有 Android WebView 外壳。暂不采用 uni-app x，也不同时替换为 App-plus 或 React Native 容器。

这一路径最贴近当前“微信小程序 + 手机 Web + WebView 安装版”，避免为统一页面同时引入第三套 App 渲染与原生集成工作。保留外壳不是兼容性已通过：产物路径、路由、返回处理、鉴权回调、定位和资源加载仍必须验证。

不强迫桌面工作台采用移动端布局或同步重写。未来新产品可复用跨端骨架、基础 UI Module、设计参数生成、Adapter 和测试；合拍自己的业务页面不进入通用模板。

## 2. 候选排序

排序依据：目标端契合、保留现有体验、少引入原生集成变更、后续多产品模板复用。属于工程判断，不是跑分排名。

| 路线 | 优势 | 代价/限制 | 判断 |
| --- | --- | --- | --- |
| 1. uni-app Vue 3，H5 + 微信；暂留 Android 壳 | Vue 的统一页面描述适合移动端跨端；现有两类运行环境即可验证；可形成模板 | 当前不是 Vue 工程，视图与生命周期仍要迁移；不能直接调用任意 DOM；版本与依赖需锁定 | 首选验证，不等于已决定全迁 |
| 2. Taro，H5 + 微信；暂留 Android 壳 | 也可达成同样目标；React 路线便于未来采用相应生态 | 当前也不是 React 工程，没有现成 React 资产优势；若另走 RN，需额外原生工具链与样式适配 | 有明确 React 偏好时可升为首选；并非技术上不适合 |
| 3. Mpx | 接近小程序开发模式，支持渐进接入、Web/RN 输出 | 若以现有小程序为母版，容易保留其视觉偏差；仍须验证复杂动画及 H5 外壳集成 | 小程序渐进改造优先时的备选 |
| 暂维持当前实现，抽共享逻辑和设计源 | 最少短期改动，不影响现有体验入口 | 页面模板仍维护两套，不能完全实现用户想要的页面源码统一 | 原型失败/不值得迁移时的回退路线，不作为长期已统一的说法 |

所有路线都可自定义视觉，不要求更换 COSPAN 的设计。uni-app 的优先级源于本项目取舍，不是证明其比 Taro 更快或更稳定；若首轮验证不通过，应重新排序。

## 3. 具体迁移成本

- **较低**：保留品牌素材、复用已批准的图标几何；后端业务无需因框架迁移重做。
- **中等**：统一颜色/字号/间距来源，迁移基础页面、表单、筛选草稿；对齐数据展示转换、请求/存储 Adapter。
- **较高**：约 6,000 行 Web 主文件中的移动端/桌面耦合、视图重构；滑卡过程与异步失败恢复；详情展开、开屏、音频生命周期；现有安装包登录/返回/资源加载兼容。
- **全量更高**：8 个小程序页面以及对应手机 Web 流程全部替换、自动化测试改接新页面、真实双用户闭环验收。不能把首个演示页面可用当成全部完成。

代码转换成本与体验验收成本都存在。换框架不会自动解决域名/TLS、微信合法域名、主体类目、通知权限或公开上架限制。

## 4. 最小验证与准入门槛（建议，尚未执行）

在独立目录与独立预览入口验证，不覆盖现有手机版本。第一阶段仅构建新 H5 与微信页面；第二阶段用隔离的 Android 测试包验证外壳集成，不覆盖用户当前安装，除非用户要求。

验证切片：**发现卡片 + 筛选弹窗 + 人物详情**。以已认可的 Web 设计和 `10-移动端视觉与字体规范.md` 为基准，不引入第三方 UI 库默认皮肤。

1. **视觉**：375/390/430 CSS px 等代表视口检查字级、页边距、卡片比例、SVG线宽、底图、弹窗；微信胶囊与安全区单独适配；用户确认最终真机效果。
2. **滑卡**：按 Web 基准核对未达阈值复位、达阈值滑出与下一卡衔接、纵向滚动不误触、快速连续操作不重复发请求、失败可恢复、资料不足引导。
3. **筛选**：三端同一数据样本产生相同结果；草稿可取消、重置不误提交、确认才生效；Demo 与 Live 数据转换显式隔离。
4. **详情/动效**：展开/收起/关闭与背景滚动、返回层级正确；开屏同心镜像与时序、音效触发及关闭设置单独做小样验证，不重设计。
5. **真实能力**：定位拒绝/允许/离页清理、过期会话、断网/超时/401、已发请求刷新确认；使用正常测试登录，不通过取消授权来跑通。
6. **安装版**：冷启动及离线静态资源、打包相对路径、页面路由、Android 返回、外链与 App Link 恢复、安全源白名单、定位桥接都通过。H5 编译成功并不代表 APK 通过。
7. **收益**：修改一处公共设计参数、筛选规则、卡片行为后，三个目标都经构建体现修改，不手工改生成物；记录实际共享文件与差异 Adapter，再判断是否值得全迁。

停止条件：为达标必须复制整套页面、关键交互无法对齐、必须放宽鉴权/域名安全、或平台补丁散落到公共页面且维护成本不降。此时保留旧版并调整候选，不因为已经写了原型继续强迁。

验收通过后顺序：移动端公共规则与发现切片 → 资料/登录/连接 → 协作通知与任务确认 → 全流程替换；桌面工作台继续独立布局。后续将不含 COSPAN 业务与密钥的工程骨架提取成模板，使用真实三端构建任务持续验证。
