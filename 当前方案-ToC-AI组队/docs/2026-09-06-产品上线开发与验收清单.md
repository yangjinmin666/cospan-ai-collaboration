更新：2026-09-06。本轮目标由用户确认：手机发现与组队，电脑持续协作，两端使用同一真实账户和数据。企业注册地址、主体申报另行推进，不阻塞产品开发。

本轮后续方向与实施建议已沉淀为[黑客松切入与人机协作产品策略](./2026-09-06-黑客松切入与人机协作产品策略.md)：同一业务与数据底座服务微信小程序、手机 App、电脑协作空间；黑客松是首个完整验证场景，核心链路包含成果提交与人工验收，硬件不作为前提。下方历史进展保留发生时的范围，不能当作所有终端当前状态。

## 交付标准

手机（微信小程序、手机安装版及手机 Web 兼容入口）：登录 → 编辑并授权资料 → 推荐 / 附近发现 → 认识请求 → 对方接受 → 邀请组队 → 本人确认入队；随后承接协作通知、任务摘要、本人领取与关键决定确认。此为目标，安装包当前 Demo/Live 模式与交付版本另行核验。

用户随后澄清的端侧边界优先于本轮初始拆分：专业任务推进、看板、任务拆解与编排在电脑完成。手机是相遇入口与协作通知伴随端，不增加完整任务编辑器。完整主链通过跨端接续完成。

电脑 Web：恢复同一身份和项目 → 切换项目 → 查看负责人、任务与执行进度 → 新建任务 → 更新执行 / 受阻 / 恢复 / 完成 / 重新打开 → 查看活动记录 → Agent 辅助与人类审阅 → 提交实际成果 → 人工验收或返工 → 确认交付。手机返回后能读取同一结果。以上为目标流程，未完成项见下表。

验收必须分开记录：代码完成、本地自动化通过、后端部署、微信预览推送、手机实测、公开发布。不能以其中一项替代其他项。

## 推进顺序

1. 先打通手机预览推送，让用户持续用真实手机反馈；每次推送记录内容和结果。
2. 补齐持续任务管理 API、电脑编辑与看板入口、手机通知与确认入口，并进行权限与双端同步测试。
3. 以两个独立账号跑完整主链，检查刷新、退出重进、多项目及断网恢复。
4. 收口原 Web 视觉迁移，手机与电脑分别看真实画面。
5. 完成运行与用户数据治理缺口，再判断产品侧是否具备公开上线条件。
